# WP05: human intent, admission and outcome

Actions bind a current run revision/generation (or a specific invocation), the proposal arguments, subject references, named reviewers, expiry and stream epoch. The server recomputes the proposal digest and rechecks both room membership and operator grants. Button intent is an immutable receipt; the external runtime must separately admit the exact action and then report its outcome. Indeterminate outcome stays indeterminate until explicit reconciliation. Reading an attention item does not resolve it.

Control requests are generated by authenticated humans only and respect declared cancel/pause/resume capabilities. No run is marked cancelled by a click. Existing preauthorized external safety behavior has no dependency on this approval mechanism. Flat primitive JSON fields are supported; remote schemas, executable UI and arbitrary extensions are rejected.

Human endpoints inherit normal session/CSRF protection and reject bearer credentials. Native agents cannot submit human decisions. Nonempty question/approval input is retained in a human-authored message and referenced by the intent receipt; the frozen receipt wire schema is unchanged. The runtime resolves that exact evidence revision before accepting it.

The action is conservatively invalidated by any changed run version. It is better to request a fresh review than apply approval to a different proposal. Production dispatch remains off; synthetic tests alone do not qualify consequential operations or a clinical deployment.
