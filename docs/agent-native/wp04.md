# WP04: run projections and semantic activity

A run has one immutable runtime/profile owner, a generation fence, monotonically increasing external revisions and an independent human-facing version/ETag. Terminal state is irreversible; retry/continuation creates a new ID. Linked runs must share a room, be visible to the creating profile and have bounded ancestry. Campfire never schedules work.

Run messages are separate rows, not room messages. Human follow-up targets a named run and profile and creates an explicit invocation. Contributors are independently room-authorized and cannot mutate owner state. Activity operations update in place using source revisions, retain attribution and link bounded evidence. Ephemeral progress expires after 30 seconds and never becomes a durable execution assertion.

Artifacts are immutable local upload references or HTTPS references; the server never fetches external references. Context resolver checks present access, room boundaries, selected revisions/hashes and history grants. Changed/unavailable context is surfaced rather than silently substituted. No agent reasoning transcript or model runtime is added.

Draft qualification: model/integration tests and common CI are supplied. Live runtime interoperability, richer artifact previews, device UX and recovery qualification belong to subsequent packages. Native production dispatch remains disabled.
