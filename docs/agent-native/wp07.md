# WP07: clients and reference integrations

The Python package under `clients/python` is dependency-free at runtime. Its CLI is a wrapper around the same transport/journal classes. An SDK-independent urllib path and the SDK both exercise a disposable Rails HTTP server in CI, including explicit invocation, admission, duplicate write replay, restart, run completion, question response and cancellation acknowledgement. Pure Python tests exercise lost acknowledgements, private storage, single ownership, epoch changes and atomic inbox/checkpoint writes.

The deterministic worker supports notification/interactive/task modes and cannot execute shell commands or infrastructure operations. A persisted per-operation effect counter makes duplicate fixture work observable. Real external effects still require each runtime's own admission, deduplication and reconciliation.

ProjectionBridge, OrcaReadOnlyBridge and conversation_binding are concrete optional integration entry points. See `integrations/README.md` for their trust boundaries and source-access limitations. No A7s repository was found through the connected installation; actual host callbacks and the full live pilot are therefore explicitly unqualified, not invented. Orca's owner process and signed human-command plane remain unchanged. Rungbee gets reusable conversation/run fixtures without a frontend migration.

The 49 frozen operations are checked against implemented routes; the same 31 frozen accept/reject fixtures exercise the Ruby validator. Passing these checks is not equivalent to full live provider conformance or production qualification. ACP/OpenClaw bridges, site MFA and arbitrary runtime provisioning are deferred.
