# WP06: human supervision

`/agent/workspace` provides pending decisions, recent runs and explicit requests. `/agent/workspace/runs/:id` separates transient observations, reported execution, run-bound conversation, immutable artifacts and collapsible semantic activity. Controls and follow-ups are capability-aware and use session/CSRF-protected forms with idempotency keys. A successful form response is intent recording, never execution confirmation. Ordinary chat is not auto-scanned for work.

`/agent/admin` is administrator-only. Register a reviewed manifest, grant rooms and human operators separately, then issue a least-privilege credential. Tokens are shown only once in an uncached response; they never enter a URL. Room grants default to `since_grant`. Revocation takes effect on the next authorized request. There is no automated legacy bot conversion.

Native artifacts use room-authorized download routes. Native uploads do not expose reusable signed Active Storage URLs. External links are HTTPS references only and are not fetched by the server. The responsive page uses labeled forms, visible focus, keyboard details/summary controls and no animation requirement. Real target-device accessibility and Web Push tests remain manual qualification gates.

Notification intents are durable and per event/subscription. Pending questions/approvals and top-level run failures notify; completion push is opt-in with `CAMPFIRE_AGENT_COMPLETION_PUSH=true` to avoid duplicate chat notifications. Progress and child activity never push. Workers recheck recipient permission before delivery. The payload is generic and carries no task content. Stable browser notification tags collapse duplicate delivery; network delivery is not claimed exactly-once. `AgentNative::Notification.drain!` retries retained intents after queue recovery, including startup/manual maintenance. No notification receipt authorizes work.

V1 limits: the page displays the latest 100 messages/operations/artifacts; the paginated API retains full authorized access. Integration registration uses a reviewed JSON manifest, not an executable plugin editor. Device evidence and sustained UX evaluation are not inferred from controller tests.
