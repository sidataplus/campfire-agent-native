# WP03: explicit invocations and replay

SQLite triggers publish identifier-only message and membership events in the same transaction as writes, including `update_all` and direct rich-text changes. Message events are observations, never instructions. The new human/session/CSRF invocation route creates a separate immutable request and event. Initial admission expires after 15 minutes and rechecks source revision, current operator permission, instance epoch and dispatch state. Requests are not admitted merely because they were delivered.

Consumers enroll at the current high-water mark. Signed cursors bind principal, consumer, authorization version and stream epoch. Every page scans a bounded number of rows; its cursor advances even when all scanned events are filtered. Authorization and direct-room scopes are rechecked. Acknowledgements cannot move beyond issued delivery or regress. State-only resynchronization never enables dispatch or clears an external deduplication journal.

Production dispatch is still disabled by the WP01 deployment gate. Synthetic development tests may enable it explicitly after setting `recovery_required: false`. WP08 supplies recovery operations; never toggle that field casually on a restored database.

Trigger definitions are deliberately in migrations. Use `db:prepare` on a clean database; WP08 preserves triggers in application-aware SQLite backups. The generic client/worker implementation is delivered in WP07, not claimed as qualified by event model tests alone.
